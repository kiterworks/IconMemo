### 0.2 产品来源声明

图标记忆是一款**独立开发的桌面图标布局管理软件**，其设计依据为：

1. **公开的用户需求**：Windows 桌面图标在分辨率切换、显示器插拔、系统更新、屏幕缩放调整后位置错乱，是长期存在的普遍问题；
2. **公开的用户手册与功能可见性观察**：本产品在立项前，参考了同类工具在公开渠道（产品官网、用户手册）上描述的功能范围，以及该类工具在正常使用中表现出的外部行为，用以确认需求的真实性与功能边界；

本产品的全部源代码均由本项目独立编写，**未复制、未移植、未改编任何第三方软件的源代码**，不包含任何第三方软件的代码片段、资源文件或数据结构定义。

## 1. 产品定位

### 1.1 解决的核心问题

在 Windows 中，桌面图标的位置是**相对坐标**，会因以下情况被打乱：

- 更换或调整主屏分辨率（如接投影、改缩放比例）
- 插拔外接显示器
- 显卡驱动更新、系统大版本升级
- 从睡眠中唤醒后显示模式变化

用户在长期使用中会形成固定的图标摆放习惯，一旦被打乱，**手动恢复 100 个图标的排列是一项非常繁琐的工作**。

### 1.2 产品价值主张

| 维度 | 说明 |
|---|---|
| 一键恢复 | 布局被打乱后，一条命令或一次点击即可还原 |
| 自动恢复 | 常驻后台，显示器环境变化时自动还原对应布局 |
| 历史可溯 | 保存布局历史，任何一版都可回滚 |
| 变化可见 | 恢复前先展示"哪些图标要移动、移到哪"，确认后才执行 |
| 无需联网 | 功能本地完成，不请求网络，不上传任何数据 |
| 免安装 | 独立可执行文件，拷贝即用，删除即卸载 |

### 2.2 布局档案

**规格要求**

| 项目 | 规格 |
|---|---|
| 存储格式 | JSON（UTF-8，可读可编辑） |
| 匹配方式 | **按图标名称匹配**，非按位置索引 |
| 档案键 | `主屏分辨率 + DPI + 显示器数`，如 `2560x1440@96dpi_1mon` |
| 缺失处理 | 档案中有、桌面没有的图标 → 单独报告"缺失" |
| 新增处理 | 桌面上有、档案中没有的图标 → 单独报告"新增"，保留原位不动 |
| 编码支持 | 完整 Unicode，中文、日文、Emoji 图标名均正确读写 |

**设计取舍说明**

以**图标名称**作为匹配键，而非图标在列表中的序号：

- 按序号匹配时，桌面任意增删一个图标，其后的全部图标都会整体错位；
- 按名称匹配时，增删图标只影响该图标本身，其余图标仍能精准归位，且可明确报告差异。

### 2.3 恢复流程规格

恢复操作按以下顺序执行，确保坐标写入后不被系统重排：

1. 读取当前桌面容器的扩展样式（自动排列 / 网格对齐的当前状态）
2. 若「自动排列图标」处于开启状态，**先关闭它** —— 该选项开启时，系统会忽略程序下发的坐标
3. 暂时关闭「对齐到网格」，避免坐标被网格吸附偏移
4. 逐个下发图标坐标
5. 恢复「对齐到网格」的对原始状态（该选项不会触发重排，可安全还原）
6. **不还原「自动排列图标」** —— 还原会立即触发系统重排，反而破坏刚恢复的布局
7. 向用户明确提示：自动排列已保持关闭，以使重启后布局保持稳定

> 说明：Windows 若开启了「自动排列图标」，会自动忽略任何程序下发的图标坐标，这是操作系统的既有行为，并非本程序的功能缺陷。

### 2.4 显示器拓扑

**规格要求**

| 项目 | 规格 |
|---|---|
| 拓扑指纹 | 逐屏记录 `分辨率 + 坐标 + 是否主屏 + 各屏 DPI` |
| 指纹示例 | `2560x1440+0+0@96*\|1920x1080+2560+0@96`（`*` 标记主屏） |
| 恢复前比对 | 档案记录环境与当前环境不一致时，明确列出差异项 |
| 坐标自适应 | 桌面可用区域变化超过 2% 时按比例缩放坐标，避免图标落到屏幕外 |
| 缩放开关 | 可通过 `--scale none` 禁用自适应缩放 |
| 越界检测 | 预演阶段报告有多少图标会落在当前桌面范围之外 |

**客观限制声明**

> Windows 的桌面图标只能存在于主屏的桌面容器内，**无法将图标放置到副屏上**。
> 外接显示器、投影、缩放比例变化，影响的都是**主屏的尺寸与 DPI**，进而影响图标坐标的有效区域。

因此"副屏独立布局"在 Windows 平台上物理上不成立。本产品对此的应对方式是：记录完整拓扑指纹，在环境变化时匹配最接近的档案并做坐标自适应。

### 2.5 快照与版本历史

**规格要求**

| 项目 | 规格 |
|---|---|
| 内容指纹 | 对「图标名称 + 坐标」计算摘要；与上一张完全一致时跳过，不产生噪声记录 |
| 变化量标注 | 列表中标注相对上一版的变化图标数 |
| 备注支持 | 可附加文字备注 |
| 默认保留量 | 最近 60 张（`--keep` 可调） |
| 回滚 | 支持按序号回滚；回滚前自动备份当前布局 |
| 自动化 | 配合常驻模式按固定间隔自动留存 |
| 命名精度 | 时间戳精确到毫秒，避免同一秒内的快照互相覆盖 |
| 缩略图 | 界面上按坐标实时绘制，不占用额外存储空间 |

### 2.6 自动恢复（常驻监视）

**规格要求**

| 项目 | 规格 |
|---|---|
| 触发方式 | 接收系统的显示配置变化通知 |
| 触发过滤 | **比对拓扑指纹**，仅在分辨率/DPI/显示器数量发生**实质变化**时执行恢复 |
| 延迟等待 | 默认等待 2 秒后执行（等系统自身的重排过程结束），可配置 |
| 去抖 | 短时间内的连续多次通知合并为一次恢复，避免重复执行 |
| 暂停 | 支持临时暂停监视，期间不响应任何变化 |
| 退出 | 支持从托盘菜单优雅退出 |

> **触发过滤的必要性**：Windows 在主题切换、环境变量变化、输入法切换、组策略更新等大量与显示器无关的场景下，也会发出同名的系统通知。若不加过滤，程序会在用户手动整理桌面时把布局"悄悄改回去"。本产品因此以**拓扑指纹是否实质变化**作为执行条件。

### 2.7 开机自动监视

| 项目 | 规格 |
|---|---|
| 注册位置 | 当前用户注册表启动项（免管理员权限） |
| 启动延迟 | 支持延迟启动，等待系统桌面环境就绪 |
| 就绪重试 | 启动时轮询等待桌面容器就绪，带退避策略与超时上限，不无限阻塞 |
| 状态查询 | 可查询当前自启注册状态与其有效性 |
| 取消 | 一条命令取消自启 |

### 2.8 图形界面

**访问方式**：仅监听本机回环地址（`127.0.0.1`），带随机令牌校验。

**界面模块**

| 模块 | 内容 |
|---|---|
| 环境卡片 | 主屏分辨率 / 缩放 DPI / 显示器数 / 当前图标数 / 自动排列与网格对齐状态 |
| 拓扑条 | 逐屏展示分辨率与主屏标记 + 虚拟桌面数量 + 当前生效的档案键 |
| 布局档案 | 全部档案列表，支持"对比并恢复"与删除 |
| 历史快照 | 每张带缩略图，标注变化量，支持"对比并回滚" |
| 桌面预览 | 按下述规则显示当前布局与目标布局的差异 |
| 底部操作 | 保存当前布局 · 另存为 · 撤销上次恢复 · 打开数据目录 |
| 退出程序 | 结束后台服务进程 |

**差异可视化规格**

| 颜色 | 含义 |
|---|---|
| 淡灰 | 不移动的图标（当前位置） |
| 橙色 | 会移动的图标（当前位置） |
| 红色 | 该图标的恢复目标位置，以虚线连回当前位置 |

**交互规格**：差异确认采用预览区下方的内联确认条（显示差异统计 + 确认/取消两个操作），不使用会遮挡对比图的系统弹窗。

### 2.9 同类工具档案导入

**功能说明**：支持读取同类桌面布局工具的档案文件，转换为本产品的档案格式。

| 项目 | 规格 |
|---|---|
| 输入 | 单个档案文件，或包含档案的目录 |
| 只读特性 | **仅读取，不修改、不移动、不删除任何原文件**；转换结果写入本产品自己的数据目录 |
| 幂等性 | 相同内容重复导入时跳过，不产生副作用 |
| 冲突处理 | 目标档案已存在且内容不同时，另存为独立名称，不覆盖用户已有档案 |
| 环境下拉 | 按档案文件中的分辨率信息推导档案键 |
| 名称保真 | 支持含空格、含中文的图标名称无损还原 |

> 该功能的目的是让用户能够延续既有的布局数据，属于软件互操作性范畴。本产品不读取、不解析该工具的二进制程序文件。

### 2.10 环境自检

`doctor` 命令对运行环境做全面检查，用于售前确认与故障排查：

| 检查项 | 说明 |
|---|---|
| 桌面容器链 | 能否定位到桌面图标容器 |
| 进程位数匹配 | 本程序与桌面进程的位数是否一致（跨进程操作要求一致） |
| 跨进程读写 | 能否在桌面进程内完成内存分配与读写往返 |
| 自动排列图标 | 当前状态（开启会影响恢复效果） |
| 对齐到网格 | 当前状态 |
| 显示器拓扑 | 屏幕数量、主屏分辨率、DPI |
| 数据目录 | 路径与可写性 |
| 单实例互斥体 | 能否正常创建 |
| 日志目录可写 | 路径与可写性 |
| 托盘图标 | 能否取得图标句柄 |
| 数据兼容性检测 | 目标机上是否存在同类工具的档案（提示二者会互相覆盖布局） |

## 3. 技术规格

### 3.1 技术选型

| 项目 | 选型 |

| 开发语言 | Python 3.9+ |

**不依赖第三方运行库的取舍**

| 收益 | 代价 |
|---|---|

| 打包体积小、启动快 | — |
| 长期可维护，不受上游库变更影响 | — |

### 3.2 系统交互方式

本产品基于 Windows 官方公开文档记载的接口实现：

| 能力 | 使用的公开接口类别 |
|---|---|
| 定位桌面图标容器 | 窗口枚举与查找 API |
| 跨进程读写图标数据 | 进程内存操作 API + 列表视图消息 |
| 读取图标名称 | 列表视图文本消息（Unicode 版本） |
| 设置图标坐标 | 列表视图位置消息 |
| 读取/设置扩展样式 | 列表视图扩展样式消息 |
| 显示器枚举与信息 | 显示器枚举 API |
| 各屏 DPI 查询 | 显示器 DPI 查询 API |
| 显示配置变化通知 | 窗口消息（显示配置变化类） |
| 系统托盘 | 通知区域 API |
| 开机自启 | 当前用户注册表启动项 |

> 跨进程访问桌面容器是该类功能所需的常规途径：桌面图标的坐标数据存储于系统桌面进程的地址空间内，程序读取或修改它需通过 Windows 提供的跨进程机制与列表视图消息完成。这是使用公开 API 的常规做法，不涉及对任何第三方程序的侵入。

## 5. 已知限制

| # | 限制 | 说明 |
|---|---|---|
| 1 | 桌面图标无法放置到副屏 | Windows 平台的客观限制 |
| 2 | 需要桌面环境运行 | 恢复功能依赖系统桌面进程存在 |
| 3 | 自动排列图标的影响 | 若该选项开启，程序会先关闭它以完成恢复，并保持关闭状态 |
| 4 | 多虚拟桌面共享图标 | 多个虚拟桌面共用同一套图标，无法各自独立；可通过命名布局实现场景切换 |
| 5 | 杀毒软件误报 | 单文件打包程序的常见现象，建议提交厂商白名单 |
| 6 | 首次启动解压 | 单文件模式下首次启动需自解压，约 1~2 秒 |
| 7 | 无数字签名 | 未签名程序在部分系统上会触发安全提示 |
